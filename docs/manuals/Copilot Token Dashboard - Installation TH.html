คู่มือการติดตั้ง Copilot Token Dashboard

1. ภาพรวม

ชุดนี้เป็นรายงาน Power BI แบบโอเพนซอร์สสำหรับติดตั้งใน tenant ขององค์กรคุณเอง มี 10 หน้า ครอบคลุมการใช้งานส่วนตัว ข้อมูลรวมขององค์กร agent โมเดล งบประมาณ สมมติฐานด้านคุณค่า และคุณภาพข้อมูล

ชุดนี้ไม่ได้ให้สิทธิ์อ่านข้อมูลขององค์กรอื่น และไม่ได้เชื่อมต่อข้อมูลภายในของ Microsoft ผู้ติดตั้งต้องใช้ tenant, workspace, สิทธิ์, ข้อมูล และ secret ของตนเอง ข้อมูลที่ให้มาสาธิตเป็นข้อมูลสมมติและมีป้ายกำกับทุกหน้า

2. สิ่งที่ต้องเตรียม

รายการใช้สำหรับ
Windows และ Power BI Desktop รุ่นปัจจุบันเปิดและตรวจรายงานบนเครื่อง
Python 3.10 ขึ้นไปตัวเก็บข้อมูล การสร้างข้อมูลรายงาน และ deployment
PowerShell 7สคริปต์ติดตั้ง
Power BI Pro, PPU หรือ Fabric capacity ที่เหมาะสมเผยแพร่และแชร์ตามเงื่อนไข license
สิทธิ์ Contributor ขึ้นไปใน workspaceสร้าง semantic model และรายงาน
Azure CLI หรือ Fabric access token ของ tenant เป้าหมายdeployment แบบอัตโนมัติ
การอนุมัติสิทธิ์จากเจ้าของข้อมูลเก็บข้อมูลจริงผ่าน API

API ในรุ่นนี้ใช้ global commercial cloud ยังไม่ได้ยืนยัน sovereign cloud หรือ GitHub host ที่กำหนดเอง ชุดนี้ไม่ได้แจกโปรแกรม Power BI Desktop

3. ดาวน์โหลดและตรวจชุด

ดาวน์โหลด ZIP ของรุ่นที่ต้องการจาก GitHub Releases ตรวจ SHA-256 เทียบกับไฟล์ checksum แล้วแตกไฟล์ลงโฟลเดอร์ใหม่ เช่น C:\CopilotTokenDashboard

Set-Location C:\CopilotTokenDashboard
.\Install.ps1 -Action Validate -InstallDependencies

คำสั่งนี้ติดตั้งเฉพาะ dependency ที่ประกาศไว้ และตรวจข้อมูลสมมติทุกตาราง ยังไม่สร้าง resource ใน tenant

อย่าปิด execution policy หรือมาตรการรักษาความปลอดภัยขององค์กร ให้ใช้กระบวนการรันสคริปต์ที่องค์กรอนุมัติ

4. เปิดข้อมูลสาธิตบนเครื่อง

.\Install.ps1 -Action Local -SourceMode Demo

สคริปต์สร้างโฟลเดอร์เฉพาะรุ่นใน local application data แล้วเปิด PBIP ไม่เขียนทับโฟลเดอร์ติดตั้งเดิม หากมีโฟลเดอร์แล้วให้กำหนด -InstallFolder เป็นโฟลเดอร์ใหม่

ใน Power BI Desktop:

1. รอให้โปรเจกต์เปิดเสร็จ แล้วกด Refresh ถ้ายังไม่มีข้อมูล

2. ตรวจป้ายข้อมูลสมมติและวันที่ Data through

3. เปิดตรวจรายงานครบทั้ง 10 หน้า

4. เลือก agent ในหน้า Agent Detail หรือใช้ drill-through ที่ตั้งค่าไว้

5. ใช้ Modeling > View as ทดสอบ role Viewer กับ UPN ตัวอย่าง

บุคคลตัวอย่างใช้โดเมน example.com และราคาตัวอย่างเป็นราคาสมมติ ไม่ใช่ราคาผู้ให้บริการหรือ rate card ที่แนะนำ

5. Publish แบบทำด้วยตนเอง

วิธีนี้ไม่ต้องใช้ token สำหรับ deployment อัตโนมัติ:

1. ลงชื่อเข้าใช้ Power BI Desktop ด้วยบัญชีของ tenant ปลายทาง

2. สร้างหรือเลือก workspace ที่องค์กรอนุมัติ

3. Publish จาก Power BI Desktop

4. ตั้ง credentials และ Refresh ใน Power BI Service

5. เพิ่มกลุ่ม Entra ที่อนุมัติให้เป็นสมาชิก role Viewer ของ semantic model

6. ทดสอบด้วยผู้ใช้ Viewer จริงก่อนแชร์หรือสร้าง Power BI App

PBIT ต้องเปิดใน Desktop ก่อน แล้วสร้างรายงานจาก template ไม่ใช่ไฟล์ที่ import ตรงเข้า Power BI Service REST API PBIP เป็น source project สำหรับแก้ไขรายงานและโมเดล ไม่ใช่โปรแกรม Power BI

6. สร้างรายงานใน tenant แบบอัตโนมัติ

ต้องระบุ tenant และ workspace อย่างชัดเจน:

.\Install.ps1 -Action Tenant -SourceMode Demo `
  -TenantId '<your-tenant-guid>' `
  -WorkspaceId '<your-workspace-guid>'

หากไม่มี CTD_FABRIC_ACCESS_TOKEN สคริปต์จะลงชื่อเข้าใช้ Azure CLI ใน tenant ที่ระบุ หรือคุณอาจตั้ง token ที่องค์กรอนุมัติใน environment ของ process สิทธิ์ที่ API ต้องการคือ SemanticModel.ReadWrite.All และ Report.ReadWrite.All หรือ Item.ReadWrite.All

สคริปต์ตรวจว่า token เป็นของ tenant เป้าหมายก่อนส่งคำขอ API ของ Microsoft ยังเป็นผู้ตรวจ signature, audience และสิทธิ์จริง

ระบบสร้าง semantic model ก่อน แล้วผูกรายงานด้วย model ID ที่สร้าง รอผล long-running operation และไม่เขียนทับ item เดิมโดยเงียบ ใช้ -Update หลังตรวจปลายทางและสำรอง definition แล้วเท่านั้น

สถานะที่ได้คือ สร้าง resource แล้ว แต่ยังต้องตั้งค่าความปลอดภัยและ refresh ยังต้องกำหนดกลุ่ม RLS, credentials, gateway ถ้าจำเป็น, app audiences และทดสอบ Viewer ก่อนถือว่าพร้อมใช้งานจริง

7. ใช้ข้อมูลของคุณเอง

อย่าใส่ข้อมูลจริงหรือ secret ลงในข้อมูลสาธิตแล้ว commit ขึ้น GitHub ให้ทำงานในโฟลเดอร์ runtime ที่ถูกตัดออกจาก source control

python -m pip install .
ctd collect-github --settings config\settings.json `
  --day 2026-05-28 --output runtime\incoming\github.jsonl
ctd collect-m365 --settings config\settings.json `
  --output runtime\incoming\m365.jsonl

คัดลอก settings.example.json เป็น settings.json ซึ่งถูก ignore ไว้ ใส่เฉพาะ tenant, app และรายละเอียด source ส่วนค่าจริงของ secret อยู่ใน environment หรือ secret manager ที่องค์กรอนุมัติ

เตรียม People.csv, Scopes.csv และ ScopeAccess.csv ตาม data contract รวม metadata ที่ผ่านการตรวจเป็น usage.jsonl อาจเพิ่ม Models, Surfaces, Agents, Budgets และ Outcomes รวมทั้ง period-summaries.jsonl จากรายงาน Microsoft 365

ห้ามกระจายยอดรวมของช่วงเวลาให้เป็นยอดรายวัน และห้ามเดา cached tokens จากยอด input tokens

ctd build-data --input runtime\incoming --output runtime\gold-2026-05-28
ctd validate-data --input runtime\gold-2026-05-28 --production

ข้อมูลจริงถูกสร้างโดยปิด demo mode scope ที่ไม่ถึงเกณฑ์ถูกตัดออก และตัวเลขของแถวที่ถูก suppress ถูกล้างก่อนเข้าโมเดล รายการที่ยังไม่มีราคาและรายการที่ยังระบุเจ้าของไม่ได้ยังคงถูกแจ้งอย่างชัดเจน

8. แหล่งข้อมูลใน Power BI

CSV บนเครื่อง

.\Install.ps1 -Action Local -SourceMode CSV `
  -DataFolder C:\CTD\runtime\gold-2026-05-28 `
  -InstallFolder C:\CTD\Customer-1.0.0

Power BI Service อ่านโฟลเดอร์บนเครื่องไม่ได้ถ้าไม่มี on-premises data gateway snapshot ที่ Publish แล้วดูได้ แต่ไม่ใช่ pipeline สดที่ refresh ได้เอง

SharePoint ใน tenant ของคุณ

อัปโหลด CSV ครบทั้งรุ่นข้อมูลที่ตรวจแล้วไปยังโฟลเดอร์ที่อนุมัติ กำหนด URL ของ site และ folder ให้ตรง รวม slash ท้าย folder และใช้ organizational OAuth credentials

.\Install.ps1 -Action Tenant -SourceMode SharePoint `
  -TenantId '<your-tenant-guid>' -WorkspaceId '<your-workspace-guid>' `
  -DataFolder C:\CTD\runtime\gold-2026-05-28 `
  -SharePointSite 'https://<your-tenant>.sharepoint.com/sites/AIReporting' `
  -SharePointFolder 'https://<your-tenant>.sharepoint.com/sites/AIReporting/Shared Documents/Gold/'

DataFolder เป็นสำเนาบนเครื่องที่ตรวจแล้วสำหรับ preflight หลัง deployment โมเดลอ่าน SharePoint ไม่ได้อ่านสำเนานั้น ต้องพบชื่อไฟล์และ folder ตรงกันเพียงไฟล์เดียว ไม่เช่นนั้นเกิด error credentials ไม่ได้รวมอยู่ในโมเดล

9. ความปลอดภัยก่อน go-live

• ใช้ role Viewer; การซ่อนหน้าใน App ไม่ใช่การป้องกันข้อมูล

• ผู้ใช้ทั่วไปควรมี Viewer หรือ app access ไม่ใช่ Member หรือ Contributor

• ไม่ให้ Build หรือ export กว้างโดยไม่มีการทบทวนข้อมูล

• ติด sensitivity label ของ tenant คุณเอง

• ทดสอบว่าผู้ใช้ A ไม่เห็น personal rows ของผู้ใช้ B

• ตรวจ scope เล็กกว่าเกณฑ์หกคนและตัวเลขแถวที่ถูก suppress

• ตั้ง refresh หลังอัปโหลดข้อมูลครบทั้ง generation แล้วเท่านั้น

• ตรวจสิทธิ์ API และ credentials ใน tenant ปลายทางจริง

• ตรวจว่าไม่มีบุคคลสมมติคงอยู่ในข้อมูล production

• ทบทวนสิทธิ์และ coverage ตามรอบ

ผู้ดูแล workspace bypass RLS ตามการทำงานของ Power BI จึงต้องเป็นผู้ดูแลข้อมูลที่เชื่อถือได้ ชุดนี้ไม่ใช่การรับรอง PDPA หรือ GDPR และไม่ใช่เครื่องมือวัดผลการทำงานของพนักงาน

10. การแก้ปัญหา

อาการสิ่งที่ควรตรวจ
Dependency ไม่ครบติดตั้งเฉพาะ package ที่ประกาศไว้
CSV header หรือ type ไม่ตรงตรวจชื่อ ลำดับ และชนิดตาม contract
Token หรือ cache ไม่มีข้อมูลตรวจ coverage ไม่แทนด้วยศูนย์
ยอดค่าใช้จ่ายไม่ตรงตรวจ billed/estimated, unattributed และ privacy suppression
Personal view ว่างตรวจ UPN mapping และสมาชิก role Viewer
Organization scope ว่างตรวจสิทธิ์ scope และเกณฑ์หกคน
HTTP 403ขอ consent หรือ role ที่ถูกต้อง ไม่ bypass
Item เดิมมีอยู่แล้วตรวจปลายทางก่อนใช้ Update
Refresh ล้มเหลวตรวจ credentials, gateway และ folder permission
Operation timeoutตรวจ workspace ก่อนสร้าง item ซ้ำ
